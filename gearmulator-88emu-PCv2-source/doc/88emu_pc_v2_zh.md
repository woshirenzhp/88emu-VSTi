# 88emuPlayer PC v2

Windows x64 VST3，四端口，每端口 16 通道。普通版与日志诊断版使用相同的 PC 修复代码，均不包含 ROM。

## PC 修复

每个端口/通道都有独立的 VST3 Unit、128 个音色的 Program List，以及带 `kIsProgramChange` 标记、`stepCount=127` 的参数。宿主可以通过标准音色接口发现并发送 PC，保留原来的 IMidiMapping 参数 ID，继续兼容此前的 DataEvent 内 `Cn pp` / `Cn pp 00` 方式。

音频组件直接解码本插件固定的 MIDI 参数 ID，不再依赖编辑控制器的直接指针。这样即使宿主通过代理连接控制器，PC、CC 与弯音的处理也不会因缺少该指针而被跳过。该修改针对连接方式的兼容性；旧日志未记录连接状态，因此不能断言它就是旧日志中 CC 异常的唯一原因。

同一采样位置、同端口、相同 PC 同时从参数与 DataEvent 到达时，只投递一次；不同采样位置以及同一参数队列中的多个点均保留。

## 使用

退出宿主后替换插件，并重新扫描插件。旧版本与新版保持相同插件 ID，宿主可能缓存旧的参数标记及音色列表，因此请确认扫描的是新文件路径，再创建新的插件实例进行测试。x86 宿主仍需要 x64 桥接。

## 逐事件日志

日志诊断版的 `88emu-midi.log` 写在外层 `88emuPlayer.vst3` 插件包旁边；请使用可写目录。可通过宿主启动前设置 `EMU88_MIDI_TRACE_PATH` 指定其他完整路径。

| 标记 | 内容 |
| --- | --- |
| `PROGRAM_LIST` | 宿主查询到的音色列表及参数 ID |
| `PC_MAP` | IMidiMapping PC 查询结果 |
| `PROCESS_INPUT` | 本次处理的采样数、事件数、参数队列数、控制器是否直接连接 |
| `PARAM` | 参数 ID 与队列点数 |
| `PARAM_READ` | 每个参数点的读取结果、采样偏移及原始归一化值 |
| `PARAM_POINT` | 成功读取并交给 MIDI 转换的每一个点 |
| `PARAM_DECODE` | 参数对应端口、1–16 通道号、控制器号、采样位置与原值；130=PC，129=弯音 |
| `INPUT_EVENT` | 每个原始 VST3 事件，包括音符，及其总线、偏移、端口启用状态 |
| `RAW_DATA` | DataEvent 子类型、总长度及前 256 字节 |
| `RAW_PC` | DataEvent 内 PC 的兼容转换及重复投递判断 |
| `DELIVER` | 每一条送入引擎队列的 MIDI，包括音符、CC、弯音、PC、完整 SysEx |

端口 0–3 对应 A–D。每行包含 Unix 毫秒时间戳。结合相同参数 ID 的 `PARAM_POINT`、`PARAM_DECODE` 与后续 `DELIVER`，可以核对参数值与采样位置。`DELIVER` 表示进入模拟器引擎队列，并不表示设备固件已经应用设置。

诊断版为启用日志的优化构建，不依赖 MSVC Debug CRT。它会逐事件同步写盘，日志量和音频线程开销高于旧版，收集完复现日志后请换回普通版。多个实例共用日志，建议测试时保留单实例。清空日志前先退出宿主。

宿主已合并到一个总线的端口标记无法在插件内恢复。SysEx 的固件应用效果也需要结合型号及实际设备状态判断。
